# 企业知识库语义检索

库内容（`E:\enterprise_data`，约 3400 块）：

- **在职员工.csv** — 员工名册：姓名、部门/组织路径、职务、职级、直线经理、邮箱、入职日期等
- **百瑞吉总部考勤规程.txt / 百瑞吉品牌一部考勤细则.txt** — 考勤及假期管理制度
- **2026年运行每日数据汇总-*.csv × 11** — 设备 JKE1~JKE5、JKQ1 及纯化水、注射用水、压缩空气、水电气、冷却水的每日监测记录（带摄取时预计算的"⚠️超标"标记，可直接作为超标证据引用）

## 用法

```bash
node E:/pi/knowledge/search.js "查询内容" [返回条数，默认5]
```

返回 top-k 相关文本块，每条带来源定位（文件 · 表/行号）和相关度（0~1，>0.7 较可信）。
回答用户时**注明来源**（哪个文件哪条记录），相关度低于 0.6 的结果不要采信。

## 员工信息的边界（重要）

检索结果可能命中员工名册，其中混有银行卡号、开户行、职业健康等敏感字段：
**绝不把银行账号/卡号/开户行写进回复，职业健康信息同样不外传**；回答员工问题只引用
姓名/部门/职务/职级/邮箱/入职日期等常规字段。涉及薪酬的话题一律不答。

## 知识库维护

- 目录有文件增删改后重新摄取（增量，按文件 hash，只处理变化的）：双击
  `E:\enterprise_data\更新向量库.bat`，或命令行 `node E:/pi/knowledge/ingest.js`。
- 摄取是离线批处理（百级文件约几分钟），不要在用户等待时随手跑；确需更新时告知用户正在后台摄取。

## 边界

- 这是**语义检索**，擅长"制度怎么规定""某人在哪个部门""哪份文件提到 X"；不擅长精确统计
  （"超标一共有几天""平均工资多少"这类应走 device-db / enterprise-data 的 SQL 技能）。
- 目前支持 txt/md/csv/docx/xlsx/文字版 PDF；扫描件 PDF 未接入（需 OCR，二期）。
