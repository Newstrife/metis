# 企业知识库语义检索

库内容（`E:\enterprise_data`，约 3400 块），**按子目录组织，目录即权限单元**：

- **考勤制度/** — 百瑞吉总部考勤规程、百瑞吉品牌一部考勤细则（考勤及假期管理制度）
- **设备监测/** — 2026年运行每日数据汇总 × 11：设备 JKE1~JKE5、JKQ1 及纯化水、注射用水、压缩空气、水电气、冷却水的每日监测记录（带摄取时预计算的"⚠️超标"标记，可直接作为超标证据引用）
- **员工名册/** — 在职员工.csv：姓名、部门/组织路径、职务、职级、直线经理、邮箱、入职日期等（敏感列已在摄取时剔除，见下）
- **流程数据/** — 2026二季度流程发起情况.xlsx

## 用法

```bash
node E:/pi/knowledge/search.js "查询内容" [返回条数，默认5]
```

返回 top-k 相关文本块，每条带来源定位（目录 · 文件 · 表/行号）和相关度（0~1，>0.7 较可信）。
回答用户时**注明来源**（哪个文件哪条记录），相关度低于 0.6 的结果不要采信。

**权限过滤**：环境变量 `KNOWLEDGE_COLLECTIONS`（逗号分隔的目录名）限定可检索的目录，
由平台按提问者的角色注入。变量存在时不要尝试绕过它去读别的目录——
那是该用户无权访问的资料。未设置时表示检索全部目录。

## 员工信息的边界（重要）

**第一道防线在摄取层（硬性）**：员工名册入库前已按白名单剔列——银行账号/开户行、
出生日期、民族、学历、职业健康/职业病、股权等敏感列**根本不在向量库里**，检索
不可能命中。回答员工问题正常使用 姓名/性别/部门/职务/职位/职级/直线经理/邮箱/
工号/入职日期 即可。

**第二道防线在行为层（自觉）**：即使如此，仍不要把 16-19 位连续数字写进回复；
涉及薪酬的话题一律不答。

## 知识库维护

- 目录有文件增删改后重新摄取（增量，按文件 hash，只处理变化的）：双击
  `E:\enterprise_data\更新向量库.bat`，或命令行 `node E:/pi/knowledge/ingest.js`。
- 摄取是离线批处理（百级文件约几分钟），不要在用户等待时随手跑；确需更新时告知用户正在后台摄取。
- 摄取管线带版本号（`lib/extract.js` 的 `PIPELINE_VERSION`）：脱敏规则或提取逻辑
  变化后版本号 +1，下次摄取自动全量重建，无需手工清库。

## 边界

- 这是**语义检索**，擅长"制度怎么规定""某人在哪个部门""哪份文件提到 X"；不擅长精确统计
  （"超标一共有几天""平均工资多少"这类应走 device-db / enterprise-data 的 SQL 技能）。
- 目前支持 txt/md/csv/docx/xlsx/文字版 PDF；扫描件 PDF 未接入（需 OCR，二期）。
